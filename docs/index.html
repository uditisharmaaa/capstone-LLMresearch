The Big Picture

Our goal is to detect whether code was written by AI. We do this by:

  1. Generate AI code samples - Ask different AI models to solve the same assignment (Connect4)
  2. Extract features - Convert each code sample into numbers that describe it
  3. Compute similarities - Measure how similar each pair of code samples is
  4. Find patterns - Do AI models produce distinctive "fingerprints"?
  5. Build a detector - Use these patterns to classify new submissions
Key Insight: Different AI models (GPT-4o, Claude, etc.) seem to produce code with different "styles" or "fingerprints". If we can measure these patterns, we can detect AI-generated code AND identify which model likely generated it.

def strip_provenance_header(code: str) -> str:
    """Remove the provenance comment header from generated code."""
    lines = code.split('\n')

    # Find the end of the provenance header
    # Looking for the closing '# ===...' line
    header_end = 0
    in_header = False

    for i, line in enumerate(lines):
        if line.startswith('# ====') and 'PROVENANCE' in lines[i+1]:
            in_header = True
        if in_header and line.startswith('# ====') and i > 5:
            header_end = i + 1
            break

    return '\n'.join(lines[header_end:])

strip_comments(code)

Removes all comments and docstrings from Python code.

def strip_comments(code: str) -> str:
    """Remove all comments from Python code."""
    # Remove single-line comments: # comment
    code = re.sub(r'#.*$', '', code, flags=re.MULTILINE)

    # Remove docstrings: """...""" or '''...'''
    code = re.sub(r'"""[\s\S]*?"""', '', code)
    code = re.sub(r"'''[\s\S]*?'''", '', code)

    # Remove empty lines
    lines = [line for line in code.split('\n') if line.strip()]
    return '\n'.join(lines)

is_valid_python(code)

def is_valid_python(code: str) -> bool:

        return True
    except SyntaxError:
        return False

Why Lexical Features?

Different programmers (and AI models) have different "writing styles":

  • Some use long variable names, others use short ones
  • Some add lots of comments, others add none
  • Some prefer list comprehensions, others use for loops
  • Some use 2-space indentation, others use 4-space

Lexical features capture these surface-level patterns.

6. TF-IDF Features (500 features)

Extracted by compute_tfidf_features(codes, max_features=500)

What is TF-IDF?

TF (Term Frequency): How often a word appears in THIS document.

IDF (Inverse Document Frequency): How rare is this word across ALL documents?

TF-IDF = TF × IDF: High score means the word is frequent in this document but rare overall — it's distinctive!

def compute_tfidf_features(codes: List[str], max_features: int = 500):
    """
    Compute TF-IDF features for a list of code snippets.

    We treat code like a document:
    - Tokens are words (variable names, keywords, operators)
    - Each code file is a "document"
    - TF-IDF captures which tokens are distinctive for each file
    """

    # Custom tokenizer splits on whitespace AND operators
    def code_tokenizer(code):
        tokens = re.findall(r'\b\w+\b|[+\-*/%=<>!&|^~]+|[(){}\[\],;:]', code)
        return tokens

    vectorizer = TfidfVectorizer(
        tokenizer=code_tokenizer,
        max_features=max_features,  # Only keep top 500 most important tokens
        ngram_range=(1, 2),       # Include single tokens AND pairs
        lowercase=False,           # Don't lowercase (case matters in code)
    )

    tfidf_matrix = vectorizer.fit_transform(codes)
    return tfidf_matrix.toarray(), vectorizer

structural.py - AST-Based Features

Location: /capstone/src/features/structural.py

Purpose: Extract features based on the code's structure using the Abstract Syntax Tree (AST). These features capture HOW the code is organized, independent of variable names or formatting.

What is an AST?

An Abstract Syntax Tree represents code as a tree structure:

# This Python code:
def add(a, b):
    return a + b

# Becomes this tree:
Module
└── FunctionDef (name='add')
    ├── arguments
    │   ├── arg (name='a')
    │   └── arg (name='b')
    └── Return
        └── BinOp
            ├── Name (id='a')
            ├── Add
            └── Name (id='b')
Why AST Features?

Two programs can look different but have the same structure:

# Version 1
for i in range(n):
    total = total + i

# Version 2 (same structure, different names)
for x in range(count):
    sum = sum + x

Lexical features see these as different (different words). AST features see them as identical (same structure: For loop → AugAssign).

The AST Feature Extractor

class ASTFeatureExtractor(ast.NodeVisitor):
    """Visitor to extract features from AST."""

    def __init__(self):
        self.node_counts = Counter()   # Count each node type
        self.max_depth = 0             # Deepest nesting
        self.current_depth = 0         # Current depth as we traverse
        self.function_count = 0
        self.class_count = 0
        self.loop_count = 0
        self.condition_count = 0
        # ... more counters

    def generic_visit(self, node):
        """Called for every node in the tree."""
        self.current_depth += 1
        self.max_depth = max(self.max_depth, self.current_depth)

        node_type = type(node).__name__
        self.node_counts[node_type] += 1

        # Track specific constructs
        if node_type == 'FunctionDef':
            self.function_count += 1
        elif node_type in ('For', 'While'):
            self.loop_count += 1
        elif node_type == 'If':
            self.condition_count += 1
        # ... etc

        # Visit all children
        for child in ast.iter_child_nodes(node):
            self.visit(child)

        self.current_depth -= 1

Cyclomatic Complexity

Measures how complex the control flow is (how many paths through the code).

def compute_cyclomatic_complexity(code: str) -> int:
    """
    Cyclomatic Complexity = 1 + number of decision points

    Decision points:
    - if/elif statements
    - for/while loops
    - and/or in conditions
    - except handlers
    - comprehension conditions
    """
    tree = ast.parse(code)
    complexity = 1  # Base complexity

    for node in ast.walk(tree):
        if isinstance(node, (ast.If, ast.While, ast.For)):
            complexity += 1
        elif isinstance(node, ast.BoolOp):
            # "and" / "or" add paths
            complexity += len(node.values) - 1
        elif isinstance(node, ast.Try):
            complexity += len(node.handlers)  # Each except clause

    return complexity
Example Complexity Scores:
  • Simple function with no branches: 1
  • Function with one if/else: 2
  • Function with nested loops and conditions: 5-10+
  • Complex game logic: 15-25+

semantic.py - Deep Learning Features

Location: /capstone/src/features/semantic.py

Purpose: Extract features using CodeBERT, a pre-trained neural network that "understands" code semantically. These features capture meaning that lexical and structural features miss.

What is CodeBERT?

CodeBERT is a neural network trained on millions of code examples. It learned to understand:

  • What code DOES, not just what it looks like
  • Relationships between functions, variables, and logic
  • Common patterns and idioms across programming languages
Analogy: If lexical features are like counting words in an essay, and structural features are like diagramming sentences, then CodeBERT embeddings are like understanding what the essay MEANS.

How It Works

class CodeBERTEmbedder:
    """Generate code embeddings using CodeBERT."""

    def __init__(self, model_name="microsoft/codebert-base"):
        # Load the pre-trained model from HuggingFace
        self.tokenizer = AutoTokenizer.from_pretrained(model_name)
        self.model = AutoModel.from_pretrained(model_name)
        self.model.eval()  # Set to evaluation mode

    def get_embedding(self, code: str) -> np.ndarray:
        """
        Get embedding for a single code snippet.
        Returns a 768-dimensional vector.
        """
        # Step 1: Tokenize the code
        inputs = self.tokenizer(
            code,
            return_tensors="pt",
            truncation=True,
            max_length=512,  # Max tokens CodeBERT can handle
        )

        # Step 2: Pass through the neural network
        with torch.no_grad():  # Don't compute gradients (faster)
            outputs = self.model(**inputs)

        # Step 3: Average all token embeddings into one vector
        # outputs.last_hidden_state shape: [1, seq_len, 768]
        embedding = outputs.last_hidden_state.mean(dim=1)

        return embedding.numpy().flatten()  # Shape: (768,)

The Output: 768-Dimensional Vectors

Each code file becomes a single vector with 768 numbers:

# For a Connect4 implementation, the embedding might look like:
[0.0234, -0.1567, 0.0891, -0.0023, 0.2341, ... # 768 total numbers]
What Do These Numbers Mean?

Each dimension captures some aspect of the code's "meaning". We can't interpret individual dimensions, but:

  • Similar code → similar vectors (close in 768-dimensional space)
  • Different code → different vectors (far apart)

This is why we use cosine similarity to compare them!

Batch Processing

def get_embeddings_batch(self, codes: List[str], batch_size=8) -> np.ndarray:
    """
    Get embeddings for multiple code snippets efficiently.

    Returns array of shape (n_samples, 768).
    """
    all_embeddings = []

    # Process in batches (8 at a time) for efficiency
    for i in range(0, len(codes), batch_size):
        batch = codes[i:i + batch_size]

        # Tokenize the batch
        inputs = self.tokenizer(
            batch,
            return_tensors="pt",
            truncation=True,
            max_length=512,
            padding=True,  # Pad shorter sequences
        )

        # Get embeddings
        with torch.no_grad():
            outputs = self.model(**inputs)

        # Mean pooling
        embeddings = outputs.last_hidden_state.mean(dim=1)
        all_embeddings.append(embeddings.numpy())

    return np.vstack(all_embeddings)  # Shape: (100, 768)

Dimension Reduction (for Visualization)

768 dimensions is too many to visualize. We can reduce to 2D:

def reduce_embedding_dimensions(embeddings, n_components=2, method='pca'):
    """Reduce 768 dimensions to 2 for plotting."""

    if method == 'pca':
        from sklearn.decomposition import PCA
        reducer = PCA(n_components=n_components)
    elif method == 'umap':
        import umap
        reducer = umap.UMAP(n_components=n_components)

    reduced = reducer.fit_transform(embeddings)
    return reduced  # Shape: (100, 2) - can now plot on x-y axes!

analysis.py - Similarity & Statistics

Location: /capstone/src/similarity/analysis.py

Purpose: Compute pairwise similarities between all code samples and run statistical tests to determine if different AI models produce distinguishable code.

Computing Similarity

Cosine Similarity

The main metric we use. Measures the angle between two vectors:

from sklearn.metrics.pairwise import cosine_similarity

def compute_pairwise_similarity(features: np.ndarray, metric='cosine'):
    """
    Compute pairwise similarity matrix.

    Args:
        features: (n_samples, n_features) array
        metric: 'cosine' or 'euclidean'

    Returns:
        (n_samples, n_samples) similarity matrix
    """
    if metric == 'cosine':
        return cosine_similarity(features)
    elif metric == 'euclidean':
        distances = euclidean_distances(features)
        return 1 / (1 + distances)  # Convert distance to similarity
Cosine Similarity Intuition:
  • 1.0 = Vectors point in exactly the same direction (identical patterns)
  • 0.5 = Vectors are somewhat similar
  • 0.0 = Vectors are perpendicular (no similarity)
  • -1.0 = Vectors point opposite directions (opposite patterns)

For code, we typically see values between 0.6 and 1.0.

Edit Distance (Levenshtein)

Used to replicate Hoq & Leinonen's methodology. Counts minimum character edits to transform one string into another:

def compute_edit_distance_matrix(codes: List[str]) -> np.ndarray:
    """
    Compute pairwise Levenshtein edit distances.

    Example:
        "hello" → "hallo" = 1 (replace 'e' with 'a')
        "cat" → "cats" = 1 (insert 's')
    """
    from Levenshtein import distance

    n = len(codes)
    matrix = np.zeros((n, n))

    for i in range(n):
        for j in range(i + 1, n):
            dist = distance(codes[i], codes[j])
            matrix[i, j] = dist
            matrix[j, i] = dist  # Symmetric

    return matrix

Grouping Similarities

Within-Group Similarities

Similarities between samples from the SAME model:

def get_within_group_similarities(similarity_matrix, groups):
    """
    Extract within-group similarities.

    Example: For GPT-4o (70 samples), there are 70*69/2 = 2,415 pairs
    """
    unique_groups = list(set(groups))
    group_indices = {g: [i for i, x in enumerate(groups) if x == g]
                     for g in unique_groups}

    within_group_sims = {}

    for group, indices in group_indices.items():
        sims = []
        for i, idx1 in enumerate(indices):
            for idx2 in indices[i + 1:]:  # Only upper triangle
                sims.append(similarity_matrix[idx1, idx2])
        within_group_sims[group] = sims

    return within_group_sims

Between-Group Similarities

Similarities between samples from DIFFERENT models:

def get_between_group_similarities(similarity_matrix, groups, group1, group2):
    """
    Extract similarities between two specific groups.

    Example: GPT-4o vs Claude = 70 * 10 = 700 pairs
    """
    indices1 = [i for i, g in enumerate(groups) if g == group1]
    indices2 = [i for i, g in enumerate(groups) if g == group2]

    sims = []
    for i in indices1:
        for j in indices2:
            sims.append(similarity_matrix[i, j])

    return sims

Statistical Tests

Mann-Whitney U Test

Tests whether two groups are significantly different (non-parametric):

from scipy import stats

def statistical_comparison(group1_sims, group2_sims):
    """Compare two groups of similarities."""

    # Mann-Whitney U test (non-parametric)
    u_stat, u_pvalue = stats.mannwhitneyu(
        group1_sims, group2_sims,
        alternative='two-sided'
    )

    # Effect size (Cohen's d)
    mean1, mean2 = np.mean(group1_sims), np.mean(group2_sims)
    std_pooled = np.sqrt((np.var(group1_sims) + np.var(group2_sims)) / 2)
    cohens_d = (mean1 - mean2) / std_pooled

    return {
        'group1_mean': mean1,
        'group2_mean': mean2,
        'mean_difference': mean1 - mean2,
        'cohens_d': cohens_d,
        'mannwhitney_p': u_pvalue,
    }
Interpreting Results:
  • p-value < 0.05: Significant difference (unlikely due to chance)
  • p-value < 0.001: Highly significant
  • Cohen's d ~ 0.2: Small effect
  • Cohen's d ~ 0.5: Medium effect
  • Cohen's d ~ 0.8: Large effect

Main Hypothesis Test

def run_hypothesis_tests(similarity_matrix, models):
    """
    Test H1: Within-model similarity > Between-model similarity

    If true, AI models have distinctive fingerprints!
    """
    within_group = get_within_group_similarities(similarity_matrix, models)

    # Aggregate ALL within-group similarities
    all_within = []
    for sims in within_group.values():
        all_within.extend(sims)

    # Aggregate ALL between-group similarities
    all_between = []
    unique_models = list(set(models))
    for i, model1 in enumerate(unique_models):
        for model2 in unique_models[i + 1:]:
            all_between.extend(
                get_between_group_similarities(similarity_matrix, models, model1, model2)
            )

    # Compare!
    results = {}
    results['within_vs_between'] = statistical_comparison(all_within, all_between)

    return results

def create_summary_report(stats, analysis_df, test_results, save_path=None):
    """Create a text summary report of the analysis."""

    lines = []
    lines.append("=" * 60)
    lines.append("AI-GENERATED CODE SIMILARITY ANALYSIS REPORT")
    lines.append("=" * 60)

    # Dataset summary
    lines.append(f"Total samples: {stats['total_samples']}")
    lines.append(f"By model: {stats['by_model']}")

    # Similarity results
    for _, row in analysis_df.iterrows():
        lines.append(f"{row['comparison']}: {row['mean_similarity']:.4f}")

    # Hypothesis test results
    for test_name, result in test_results.items():
        lines.append(f"p-value: {result['mannwhitney_p']:.2e}")
        lines.append(f"Cohen's d: {result['cohens_d']:.4f}")

    report = "\n".join(lines)

    if save_path:
        with open(save_path, 'w') as f:
            f.write(report)

    return report
