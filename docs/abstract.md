## Abstract

The release of large language models (LLMs) such as ChatGPT in November 2022 fundamentally changed the academic integrity landscape in computer science education. LLMs can produce syntactically correct, functionally complete code for standard programming assignments within seconds, making it trivially easy for students to submit AI-generated solutions as their own work. Traditional similarity tools such as MOSS detect copying between submissions using document fingerprinting [1], but are entirely ineffective against AI-generated code: each generation is unique and shares no source document with any other. Surveys of introductory CS students report AI tool usage rates exceeding 25% [2], yet detection infrastructure has not kept pace.

Prior work on AI code detection has made progress but remains narrow in scope. Hoq et al. (SIGCSE 2024) demonstrated that machine learning models can distinguish ChatGPT-generated Java code from human-written code with up to 97% accuracy on simple CS1 problems [3]. Xu and Sheng (AAAI 2024) applied perplexity-based methods to detect AI-generated assignment code, achieving AUC 0.87 [4]. However, both studies tested only a single AI model against short, simple programs. In practice, students have access to a rapidly expanding set of AI tools — GPT-4o, Claude, Gemini, Llama — and instructors assign longer, more complex problems. It remains an open question whether AI code fingerprints persist across different models and realistic assignment complexity, and whether different models leave distinguishable signatures.

This project addresses both questions through two research contributions. **RQ1 (multi-model fingerprinting):** Do different AI models leave statistically distinguishable stylistic fingerprints in CS1 assignment code, and do those fingerprints persist across 15 prompt-level style variations? **RQ2 (AI vs. human detection):** Can a supervised classifier reliably separate AI-generated submissions from pre-ChatGPT student code on the same assignment?

For RQ1, we constructed a controlled dataset of 423 Connect4 Python implementations generated by 9 LLMs spanning two generations: a 2024 cohort (GPT-4o, GPT-4o Mini, Claude Sonnet 3.5, Gemini 2.0 Flash, Llama 3.1 70B, Claude Opus 4.5) and a 2025 cohort (OpenAI o4-mini, Claude Sonnet 4.6, Claude Opus 4.6). Each model was prompted under 15 distinct coding style instructions (beginner-friendly, compact, PEP8-compliant, modular, etc.) to test whether fingerprints survive surface-level variation. From each file we extract three complementary feature representations: (1) lexical features via TF-IDF over token unigrams and bigrams, (2) structural features from Abstract Syntax Tree analysis including cyclomatic complexity, nesting depth, and function count, and (3) semantic features via CodeBERT embeddings [5] (planned for full-paper phase). Pairwise cosine similarity matrices are computed for each feature type, and within-model versus between-model similarity distributions are compared using Mann-Whitney U tests with Cohen's d effect sizes.

Preliminary results on TF-IDF similarity demonstrate that AI models produce statistically distinguishable fingerprints: within-model similarity (mean 0.793) significantly exceeds between-model similarity (mean 0.719), with Cohen's d = 0.720 and p < 0.001. Of 36 pairwise model comparisons, 27 are highly significant (p < 0.001) and 33 are significant at any level. GPT-4o Mini has the highest internal consistency (mean 0.833), while Claude Sonnet 4.6 shows the most variation (mean 0.710, std 0.165). Two non-significant pairs involve Anthropic models (Claude Opus 4.5 and Claude Sonnet 3.5), consistent with same-company architectural overlap reducing lexical distinguishability. We note that Gemini 2.5 Flash and Pro were excluded from the final analysis after generating truncated ~20-line files: these thinking models consumed their token budget on internal reasoning, leaving insufficient output — a reproducible methodological finding about the limits of applying thinking models to code generation tasks with fixed token budgets.

For RQ2, the pre-November 2022 student Connect4 submissions (collected prior to LLM availability) are in hand from the course instructor. In Fall 2026, we will train a Random Forest and XGBoost classifier to distinguish AI-generated from human-written code, outputting probability scores rather than binary labels to minimize false accusations. The assignment-specific design — rather than a general-purpose detector — is intentional: it exploits the fact that instructors reuse the same assignments annually, and that human baselines from pre-ChatGPT semesters serve as clean ground truth.

This work makes three contributions beyond prior art. First, it is the first multi-model fingerprinting study on CS1 assignment code, covering 9 models spanning two LLM generations (2024–2025), compared to the single-model scope of all prior work. Second, it uses a verified pre-ChatGPT human baseline rather than GitHub open-source code as a proxy for human writing, which better reflects the actual detection target in educational settings. Third, it operates on assignment-complexity Python programs (~110 lines average) rather than the short snippets (~10 lines) evaluated in prior work, providing evidence that fingerprints persist at realistic problem sizes.
